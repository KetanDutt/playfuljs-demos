# Architecture

## Design goals

Playful.js is a static, portable creative-coding collection. Every experience owns its HTML, CSS, and JavaScript and can run independently. Keeping the demos framework-free minimizes transfer size and preserves their educational value.

## Gallery

`index.html` is the discoverable project entry point. It contains no JavaScript and links to each experience using relative URLs, so deployment works at any path.

## Maze Runner

The raycaster uses a 2D `Uint8Array` as its world grid. A depth-first maze generator carves passages and places the goal at the deepest point reached. For each vertical screen column, `Map.cast` walks grid intersections and `Camera.drawColumn` projects the nearest wall slice. Billboard sprites are distance-sorted and clipped against wall distance.

Main runtime objects:

- `Controls`: keyboard and pointer state.
- `Player`: movement, stamina, health, weapons, and combat.
- `Map`: collision grid, textures, ray traversal, and sprites.
- `Camera`: projection, rendering, minimap, HUD, and visual feedback.
- `Objects`: enemy lifecycle and updates.
- `GameLoop`: requestAnimationFrame scheduling with delta-time safeguards.

Audio is synthesized after user interaction through Web Audio. Images are cached by URL so enemy instances reuse decoded assets. Rendering resolution and device pixel ratio are capped to prevent excessive GPU and memory use.

## Other demos

The particle demos use Verlet-style position integration and additive blending. Particle counts and device scale are bounded. They skip simulation while hidden. Terrain uses a typed height map generated by diamond-square subdivision and projects vertical samples into an isometric view.

## Security and privacy

There is no user input persistence, remote content, telemetry, service worker, or backend. The deployment workflow publishes only repository files after a static integrity check.
